# Every line is coverage we are NOT getting. Justify it or delete it.
# Format:  TestName   # why
#          TestName   # why [requires: corpus:NAME tool:NAME env:NAME]
#
# The optional [requires: ...] marker (#854) says what the test needs in
# order to RUN. When every listed prerequisite is present, this gate expects
# the test to run and stays silent about it; when any is absent (as on CI) it
# expects the skip, exactly as before. That is what lets one allowlist be
# correct both on a corpus-less CI runner and on a corpus-equipped dev box.
# An entry with NO marker keeps the original unconditional behaviour.
# A skip that is not listed here fails the gate regardless — never relaxed.
#
# [Theory] TESTS: use the BARE METHOD NAME, never one entry per row. This gate
# strips theory arguments from the names it observes, so `Method(param: "x")`
# is compared against a name that never has arguments and matches nothing —
# it then reports as "allow-listed skip is no longer skipping" on every run
# where the test does skip. One entry per method covers every row.
#
# (The two veraPDF-gated conformance tests that used to sit here now RUN on
# CI — coverage came back with the trx-based enumeration + CI's veraPDF
# availability, so their entries were removed per the gate's instruction.
# They still skip on local machines without veraPDF installed; the
# allowlist's reference environment is CI, not any one dev machine.)
